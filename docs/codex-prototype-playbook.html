Codex Prototype Playbook

Інструкція для команди дизайнерів: як запускати прототипи в Codex так само, як у цьому проекті.

1. Обов'язкові умови

  • GitHub репозиторій підключений до Vercel.
  • У Vercel додані змінні для API реєстру прототипів (Supabase): SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, SUPABASE_TABLE.
  • Є доступ до Figma файлів і Storybook дизайн-системи.
  • У локальному середовищі встановлено Node.js та npm.

2. Стандартний workflow

  1. Додайте новий прототип на Dashboard через кнопку Новий прототип (назва + href + folder).
  2. Надішліть Codex посилання на Figma node(s) і, за потреби, посилання на Storybook компонент.
  3. Codex реалізує сторінку у відповідній папці прототипу.
  4. Codex додає/оновлює стейти компонентів за Storybook.
  5. Codex пушить у main, Vercel автоматично деплоїть.
  6. Після перевірки змініть статус прототипу з draft на active через API/дашбордний процес.

3. Master prompt (базовий)

Використовуйте цей шаблон як стартове повідомлення для Codex.

Зроби прототип за Figma 1:1 без спрощень. Figma node links: - [вставити лінки] Обов'язково: 1) Використовуй стейти компонентів зі Storybook (default/hover/focus/active/disabled/error/selected). 2) Іконки тільки з Figma/design system, без placeholder. 3) Додай адаптивність для tablet/mobile. 4) Після змін зроби commit + push в main. 5) Поясни що саме оновлено і дай шлях до файлів.

4. Master prompt (для доопрацювання існуючого прототипу)

Онови існуючий прототип [назва/папка] за Figma. Вимоги: - Перевір всі відступи, типографіку, іконки, стейти. - Звір компоненти з Storybook і виправ розбіжності. - Не змінюй бізнес-логіку поза цією задачею. - Зроби responsive версію без ламання desktop. - Пуш в main і короткий changelog.

5. Правила якості (Definition of Done)

  • Figma fidelity: 100% (компоненти, іконки, розміри, падінги, типографіка).
  • Storybook states: всі релевантні стани присутні й працюють.
  • Responsive: desktop/tablet/mobile без поламаних блоків.
  • Dashboard link веде на робочий URL прототипу.
  • Код закомічений і задеплоєний через Vercel.

6. Швидкий чек-лист перед релізом

  • Чи співпадають тексти і лейбли 1:1 з макетом?
  • Чи є hover/focus/active/disabled/error стани кнопок/інпутів?
  • Чи не використовуються емодзі замість іконок?
  • Чи відкривається лінка прототипу з Dashboard без 404?

7. Як створити індивідуальний Dashboard для нового прототипу

  1. Створіть окрему папку прототипу, наприклад: prototype-owner-change/.
  2. Додайте в папку сторінку-дашборд index.html з блоками навігації по екранах вашого прототипу.
  3. Якщо прототип має кілька сторінок, додайте внутрішні лінки, наприклад: /prototype-owner-change/step-1/, /prototype-owner-change/step-2/.
  4. Додайте запис у головний реєстр через кнопку Новий прототип на основному Dashboard:
    Назва: Owner change verification flow
    Лінка: /prototype-owner-change/
    Фолдер: prototype-owner-change/
  5. Поки сторінка не готова, залишайте статус draft. Після готовності переведіть у active.
  6. Попросіть Codex додати/оновити індивідуальний dashboard та перевірити, що всі внутрішні лінки відкриваються без 404.
Створи індивідуальний dashboard для прототипу [назва]. Потрібно: 1) Окрема папка [folder] з index.html як точка входу. 2) Секція \"Екрани прототипу\" з лінками на всі кроки. 3) Блок \"Статус\" (draft/active) і короткий опис. 4) Адаптивність desktop/tablet/mobile. 5) Додай цей прототип у головний Dashboard реєстр (href + folder + notes). 6) Перевір, що немає 404 і закоміть зміни.

8. Крок за кроком: як віддати процес іншій команді через копію репозиторію

  1. Увімкніть шаблон репозиторію в GitHub:
    `Settings` → `General` → `Template repository` → увімкнути.
  2. Дизайнер/команда створює свою копію:
    `Use this template` → `Create a new repository`.
  3. Підключіть новий репозиторій до Vercel:
    `Add New` → `Project` → імпорт нового repo → `Deploy`.
  4. У Vercel додайте env змінні:
    SUPABASE_URL
    SUPABASE_SERVICE_ROLE_KEY
    SUPABASE_TABLE (наприклад prototypes)
  5. Якщо база нова, створіть таблицю в Supabase SQL Editor:
create table if not exists public.prototypes ( id uuid primary key default gen_random_uuid(), name text not null, slug text not null unique, status text not null default 'draft' check (status in ('draft', 'active', 'archived')), folder text not null, href text not null, notes text not null default '', created_by text not null default 'dashboard', created_at timestamptz not null default now() );
  1. Зробіть `Redeploy` у Vercel після додавання env.
  2. Перевірте головний dashboard:
    відкрийте URL проекту, створіть тестовий запис через кнопку `Новий прототип`.
  3. Додайте перший робочий прототип:
    `href`: /prototype-name/, `folder`: prototype-name/.
  4. Перевірте, що лінка відкривається без 404 і лише після цього ставте статус `active`.

9. Troubleshooting (симптом → причина → рішення)

  • 404 NOT_FOUND на лінці прототипу → папка/роут не існує або неправильний `href` → створіть `index.html` у правильному folder і звірте `href` у реєстрі.
  • Dashboard в read-only fallback → API не бачить Supabase env → перевірте `SUPABASE_*` у Vercel і зробіть redeploy.
  • Push відхилено через workflow scope → GitHub PAT без `workflow` scope → створіть новий PAT з `repo` + `workflow`, оновіть креденшали.
  • Компоненти не схожі на макет → пропущені стейти зі Storybook → вимагайте повний набір state: default/hover/focus/active/disabled/error/selected.
  • Codex не бачить Figma → немає токена або доступу до файлу → перевірте Figma token та права на конкретний файл/node.
